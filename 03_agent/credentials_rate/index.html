    credentials_rate.md — 凭据池与限速记账¶

    文件概览¶

    一个长寿命 Hermes 进程（网关同时跑几十个会话）要回答四类问题：这个 provider 现在用哪把 凭据（池与轮转）、凭据坏了怎么办（冷却、隔离、刷新、恢复）、我离限流还有多远 （头部捕获、跨会话熔断、credits）、这些 token 花了多少钱（锚点记账、计价、用量/账单 视图）。27 个文件分担这些职责，没有一个是"顺手的散装代码"——凭据边界和钱都是审计对象。

    组 文件 职责
    池核心 credential_pool.py + 4 兄弟 多凭据池：选择、轮转、冷却、刷新、管理端
    多源凭据 credential_sources.py / credential_source.py / anthropic_credentials.py / command_token_source.py / credential_persistence.py / credential_auth_recovery.py / custom_entry_pool.py 来源读取、借用、key_cmd、磁盘边界
    限速 rate_limit_tracker.py / rate_limit_credits.py / nous_rate_guard.py / credits_tracker.py 头部捕获、低额度通知、跨会话熔断
    记账 usage_anchor.py / usage_pricing.py / usage_gauges.py / aux_accounting.py 锚点计数、美元计价、窗口余量、aux 归账
    视图 account_usage.py / account_usage_cache.py / subscription_view.py / plan_limits.py / billing_usage.py / billing_view.py / billing_links.py /usage 与 /subscription 的数据与渲染

    关键代码走读¶

    1. PooledCredential —— 池行的全部状态（credential_pool.py:209）¶

    # agent/credential_pool.py:209-239（节选）
class PooledCredential:
    provider: str
    id: str
    label: str
    auth_type: str
    priority: int
    source: str
    access_token: str
    refresh_token: Optional[str] = None
    last_status: Optional[str] = None          # OK / EXHAUSTED / DEAD / ...
    last_status_at: Optional[float] = None
    last_error_code: Optional[int] = None
    last_error_reason: Optional[str] = None
    last_error_message: Optional[str] = None
    last_error_reset_at: Optional[float] = None
    # Epoch of the last deliberate ``hermes auth reset`` of this entry. Sticky: a later exhaustion
    # stamps a newer ``last_status_at``, so "reset postdates status" stays decidable across processes.
    status_cleared_at: Optional[float] = None
    base_url: Optional[str] = None
    expires_at: Optional[str] = None
    expires_at_ms: Optional[int] = None
    ...
    request_count: int = 0
    # A provider may rate-limit one model while the same credential remains
    # usable for its sibling models.  Keep that observation separate from the
    # credential-wide status used for auth and billing failures.
    model_cooldowns: Optional[dict[str, float]] = None
    extra: dict[str, Any] = None  # type: ignore[assignment]

    三处设计值得记住：

    • status_cleared_at 是粘性的（:224-226）：后续的 exhaustion 会盖新的时间戳， 所以"reset 晚于 status"这条判定跨进程永远可决。
    • 模型冷却与凭据级状态分离（:235-238）：provider 可以只限流一个模型，同一凭据的 兄弟模型照常可用——这个观察放在 model_cooldowns，不污染 auth/billing 失败用的 last_status。
    • extra 是插件的载荷（from_dict，:252-272）：非字段键全部进 extra 往返， 插件存在自己行上的元数据在 load→save→load 之后幸存；provider 永远是行的所有者， 不许被扫进元数据。

    runtime_api_key / runtime_base_url（:287-316）是运行时读取面：Nous 的推理凭据 是 agent_key（必须是可用的 NAS invoke JWT）；openai-codex 的行保存规范 ChatGPT URL， 但 profile 级代理覆盖必须赢——否则一次 401/429 轮转会静默离开代理。

    2. _available_entries 与 mark_exhausted_and_rotate —— 选择的纪律（credential_pool.py:2030, 2255）¶

    # agent/credential_pool.py:2030-2056 + 2090-2105（节选）

        self, *, clear_expired: bool = False, refresh: bool = False, model: Optional[str] = None,

        *clear_expired* resets elapsed cooldowns to STATUS_OK and persists.
        *refresh* refreshes entries needing a token refresh (skipped on

        xai-oauth), which are returned as *pending_refresh* so the caller
        refreshes them outside the lock instead of stalling every pool
        consumer during cross-process flock acquisition + OAuth network I/O.
        """
        ...
            if entry.last_status == STATUS_DEAD:
                # Manual DEAD credentials are pruned after a 24h quiet window;
                # singleton-seeded ones stay (audit trail, and the seeder would
                # re-create them anyway). DEAD never re-enters via TTL — only a

    可选用途过滤的完整链条：借用凭据未水合的不租（防发空 key）、DEAD 行手动来源 24h 后 修剪（singleton 播种的留着——审计线索，反正播种器会重建）、DEAD 永不经 TTL 复活 （只有写侧的 re-auth 同步能清）、单 use token provider 的刷新推迟到锁外（不在跨进程 flock + OAuth 网络往返中卡死所有池消费者）。

    # agent/credential_pool.py:2255-2275 + 2281-2300（节选）
    def mark_exhausted_and_rotate(self, *, status_code, error_context=None, api_key_hint=None,
                                  credential_id=None, failure_reason=None, model=None):
        with self._lock:
            identity_supplied = bool(credential_id or api_key_hint)
            entry = self._identify_failed_entry(credential_id, api_key_hint)
            ...
            if self._is_model_scoped_failure(status_code, model, failure_reason):
                # A generic Anthropic 429 (per-model rate limit) or a Codex account model
                # entitlement rejection: bench this model only, the credential stays
                # available for its siblings.
                self._cool_down_model(entry, model, error_context, failure_reason=failure_reason)
                ...
            self._mark_exhausted(entry, status_code, error_context, failure_reason=failure_reason)
            # A 402/429/401 is a key-level failure, and the same key can back
            # several entries (an explicit entry plus a ``model_config`` row
            # auto-seeded from ``model.api_key``). Marking only the first
            # leaves siblings OK, ``_select_unlocked()`` keeps handing back
            # the depleted key, and rotation never converges (~2.5 min hang).
            # Mark every entry sharing the failed key.
            failed_runtime_key = entry.runtime_api_key
            if identity_supplied and failed_runtime_key:
                siblings = [
                    s for s in self._entries if s.id != entry.id and s.runtime_api_key == failed_runtime_key
                ]
                for sibling in siblings:
                    self._mark_exhausted(sibling, ..., persist=False, ...)

    轮转的两条硬规则：模型级失败只冷却模型（Anthropic 泛 429、Codex 模型权益拒绝—— 凭据留给兄弟模型）；key 级失败连坐所有同 key 条目（同一个 key 可以支撑多条 pool 行，只标记第一条的话 _select_unlocked 会一直把耗尽的 key 发回来，轮转永不 收敛，症状是 ~2.5 分钟挂起）。

    3. 播种器与借用凭据（credential_pool.py:2521 + credential_persistence.py）¶

    池不是凭空来的：_Seeder（:2521）从单例播种——_seed_anthropic_singletons（: 2545）、_seed_nous_singleton、_seed_profile_singleton、_seed_qwen_singleton、 _seed_minimax_singleton。anthropic_credentials.py 的头注释点出契约：

    ~/.hermes/.anthropic_oauth.json (Hermes PKCE) and the Claude Code file are singletons: credential_pool._seed_from_singletons() re-reads them on every load_pool(), so a failed write here is a failed refresh.

    "借用"凭据（Codex CLI 的 ~/.codex/auth.json、Claude Code 的 ~/.claude/.credentials.json）有专门的政策文件。credential_persistence.py 管磁盘 边界：借用的池行持久化为仅元数据引用，原始秘密在到达 auth.json 前剥掉（ sanitize_borrowed_credential_payload），并且刻意不 import hermes_cli.auth——池模型 与 auth-store 写边界共享一套策略而不产生环。还有"已花轮转"侧车（_spent_rotation_sidecar_path， :151）：single-use refresh token 是一次性的，指纹记下来防止把已消费的轮转当成新鲜对。

    credential_sources.py 统一的是移除契约（:1-13）：

    Readers live in agent.credential_pool; what is unified here is removal: hermes auth remove <provider> <N> must make the entry stay gone across load_pool() calls. Each source registers a RemovalStep ... and the dispatcher suppresses (provider, source_id) in auth.json so the seeding branch skips the upsert.

    不加这个，hermes auth remove 会在下一次 load_pool() 时被播种器原样复活。 借用 CLI 登录的政策开关 auth.adopt_external_logins（默认 True）也在这里：Codex 和 Claude 的 OAuth refresh token 是单次使用且轮转的——Hermes 一旦借走 CLI 的 token 对， 两个程序就共享一个 token 族，谁先刷新谁把对方登出（:24-33）；opt-out 后 Hermes 永不 读/刷新那些文件，并每进程 INFO 一次。

    4. 刷新与恢复（credential_pool.py:1490 + credential_auth_recovery.py）¶

    _refresh_entry（:1490）是刷新总入口，按 provider 分派到 _refresh_anthropic（Claude OAuth PKCE）、Codex（single-use、带 CODEX_ACCESS_TOKEN_REFRESH_SKEW_SECONDS 提前量）、 插件 refresh hook（credential_pool_plugin.py，#116408）等；失败走 _recover_failed_refresh / _mark_dead_refresh_grant——终态（invalid_grant）会清理 token 并写隔离标记。_fail_closed_unpersisted_rotation（:1547）处理最危险的窗口： 轮转已消费但尚未持久时绝不放行（fail-closed），宁可拒绝也不把不可复现的 token 族留在内存里。

    credential_auth_recovery.py 是 401/403 的恢复路径：调度到的凭据认证失败时，先同步 外部来源（auth store / 凭据文件可能已被别的进程刷新），同步失败才标记并轮转—— 多进程共享 auth.json 时，"过期"经常只是"别的进程刚刷新、我拿到旧值"。

    5. 限速捕获与跨会话熔断¶

"""Rate limit tracking for inference API responses.

Captures ``x-ratelimit-{limit,remaining,reset}-{requests,tokens}[-1h]``
headers (Nous Portal format, also used by OpenRouter / OpenAI-compatible APIs)
and formats them for the /usage slash command. Reset values are seconds."""
_BUCKET_TAGS = (
    ("requests_min", "requests"),
    ("requests_hour", "requests-1h"),
    ("tokens_min", "tokens"),
    ("tokens_hour", "tokens-1h"),
)

    四个窗口（分钟/小时的请求数与 token 数）一次捕获成 RateLimitBucket。 rate_limit_credits.py 是 AIAgent Mixin 侧的粘合层：解析响应头进 _rate_limit_state/_credits_state 并发粘性通知——解析面在 Mixin（保持 run_agent 同名的 logger），策略面在 tracker。

    nous_rate_guard.py 解决一个具体的放大问题：

    # agent/nous_rate_guard.py:1-6
"""Cross-session rate limit guard for Nous Portal.

Writes rate limit state to a shared file so all sessions (CLI, gateway, cron,
auxiliary) can check whether Nous Portal is currently rate-limited before making
requests. Without it each 429 fans out into up to 9 calls per turn (3 SDK
retries x 3 Hermes retries), all counted against RPH."""

    共享文件是跨会话熔断器：所有会话（CLI/网关/cron/auxiliary）请求前先看一眼，一个 429 不再引发每 turn 最多 9 次的连锁。两个阈值讲究：reset < 60s 是上游抖动，不值得跳闸； welcome tier 的结构化 rate_limited 拒绝里，reset ≥ 阈值是配额耗尽（停下、告诉用户 何时刷新、登录可解除），低于阈值则等一等就好。

    credits_tracker.py（940 行）管 Nous credits：把 x-nous-credits-* / x-nous-tool-pool-* 头解析成校验过的 CreditsState——钱是 micros 整数， *_usd 字符串原样保留（绝不重新解析成 float），schema 版本不认识就 warn-once 放行。

    6. 用量锚点 —— 本地估算只算增量（usage_anchor.py:1-11）¶

    # agent/usage_anchor.py:1-11
"""Usage-anchored token accounting: the provider's real ``usage.prompt_tokens`` is the only
authoritative context size; the local ``bytes/4`` estimate covers ONLY messages appended since.

An anchor = provider usage at capture + a snapshot of the transcript position it priced:
``base_count`` (len(messages) at capture; the reply is not yet appended and is covered by
``completion_tokens``, so the delta walk skips an assistant row at that index), ``base_last_role``
and ``base_last_fp`` (content fingerprint of the last priced message; compaction, splices and
rewinds replace it → anchor fails closed → full estimation until the next real reading).

The fingerprint (not ``id()``) is the identity: the gateway re-reads the transcript from the DB
every turn and a resumed session runs in a fresh process, so object identity is never stable
across the surfaces where the estimate mattered most (#99421, #104462). The anchor also persists
on the session row (``model_config._usage_anchor``) so a restarted process can restore it; a
restored anchor is honored only while the durable transcript still matches its fingerprint."""

    计数的信用等级很明确：provider 的真实 usage.prompt_tokens 是唯一权威，本地 bytes/4 粗估（model_metadata.md §2）只覆盖锚点之后追加的消息。锚点身份用内容指纹 （_FINGERPRINT_KEYS = ("role", "content", "api_content", "tool_call_id", "tool_calls")， :23）而不是 id()——网关每 turn 从 DB 重读转录、恢复的会话跑在新进程里，对象身份 在最需要它的地方恰恰不稳定。锚点对不上（压缩/拼接/回退改了转录）就失败关闭： 退回全量估算，直到下一次真实读数。锚点随会话行持久化，重启的进程可恢复，恢复的锚点 只在持久转录仍匹配指纹时被采纳。

    7. 计价与视图¶

    usage_pricing.py（799 行）把 token 变成美元：价格优先从 OpenRouter 元数据的 pricing 字段（model_metadata.md §4 预热的缓存）与端点 /models 定；_MODELS_DEV_DIRECT_HOSTS （:23-27）列明哪些一方按量计费 API 可以直接用 models.dev 牌价——且只在直连该域名 （HTTPS:443）时：代理/中继/自定义端点卖同一个模型 id 可以不同价，订阅路由 （openai-codex、xai-oauth）有自己的政策。显示层为 sub-cent 成本渲染 4 位小数 （"\(0.0046" 而不是 "\)0.00"）。

    aux_accounting.py 把 aux 调用的用量归回会话：aux 客户端没有会话句柄，历史上用量 直接丢弃——agent 循环把 (session_db, session_id) 发布进 ContextVar（镜像 portal_tags 的作用域纪律，HX002 家族），aux 客户端在它唯一的响应校验咽喉点记账。 _EXCLUDED_TASKS 排除 moa_reference/moa_aggregator——它们已折进 conversation_loop 的 delta，再记一次就双算。

    视图四件套共享同一数据面：billing_usage.py 是 /usage 与 /subscription 通用条的 美元用量模型；usage_gauges.py 按服务器发来的显示顺序维护用量窗口余量； plan_limits.py 回答"一个限额挡住了什么、改提供什么"；account_usage.py（975 行） 是各 provider 账户用量的取数引擎（Anthropic OAuth、Codex、OpenRouter、Portal… 各有一套窗口），account_usage_cache.py 让 model.options 在不打网络的情况下知道 订阅用量；billing_view.py 是 Remote Spending 屏幕的 surface 无关核心（CLI 与 TUI JSON-RPC 共用）；billing_links.py 给账单类失败配 provider 无关的"恢复链接"。

    总结¶

    • 池是一条状态机：每行凭据带状态（OK/EXHAUSTED/DEAD）、模型级冷却、刷新计划与 extra 载荷；选择过滤 DEAD 与冷却（单 use provider 的刷新推迟到锁外）；DEAD 永不经 TTL 复活。
    • 轮转的粒度即失败粒度：模型级失败（429/权益拒绝）只冷却模型；key 级失败 （402/429/401）连坐所有共享该 key 的条目——否则轮转永不收敛。
    • 凭据有来源也有去处：单例播种（Hermes OAuth、Claude Code、~/.codex）、key_cmd、 custom providers；移除必须登记 RemovalStep，否则 hermes auth remove 被播种器复活。 借用凭据在磁盘边界消毒、已花轮转记指纹侧车。
    • 限速有三层：响应头捕获（四窗口）、跨会话熔断（共享文件防一个 429 放大 9 次）、 credits 状态机（micros 整数，字符串保留，warn-once 版本门）。
    • 记账以 provider 为权威：真实 usage.prompt_tokens 是锚点，本地粗估只算增量； 锚点用内容指纹定身份（跨进程/跨 DB 重读都稳定），对不上就失败关闭退回全量估算。 aux 调用经 ContextVar 归账，MoA 双算被显式排除。
    • 计价认直连：models.dev 牌价只对一方 API 的直连域名成立，代理与订阅路由各有 各的账；sub-cent 成本渲染到 4 位小数，绝不显示 $0.00。
