    turn_facade.md — 准入门面：AIAgent、租约与 Mixin 拼装¶

    文件概览¶

    用户消息要进入 conversation_loop.run_conversation 那颗心脏之前，必须先过一道安检门。 这道门由三份文件共同把守：

    文件 行数 角色
    agent/turn_facade.py 224 TurnFacadeMixin：AIAgent.run_conversation / chat 的正式入口
    agent/turn_facade_lease.py 495 跨进程会话 turn 租约：准入、续租线程、停滞看门狗接线
    run_agent.py 1,565 公共门面：AIAgent 类 = 14 个 Mixin 拼装；__init__ 是纯转发器
    agent/agent_init.py 2,211 init_agent：构造的真正实现（相位顺序 load-bearing）
    agent/iteration_budget.py 60 线程安全的迭代预算（父子共享）

    根 AGENTS.md 对这个布局的概括：run_agent.py is the public facade: AIAgent is assembled from mixins; Construction runs agent/agent_init.py::init_agent; a turn is agent/conversation_loop.py::run_conversation, which AIAgent.run_conversation forwards to after taking the session turn lease (turn_facade_lease.py).

    用户消息
   ▼
AIAgent.run_conversation   (turn_facade.py:22，TurnFacadeMixin)
   │ ① cancel_background_review_for_live_turn  后台 review 让路
   │ ② admit_durable_turn_lease  ← 跨进程准入（另一进程在用就等/退）
   │ ③ relay/accounting/portal scopes  ④ bind_subagent_parent / interrupt scope
   │ ⑤ lease.start()（续租线程 + 看门狗上线）
   ▼
conversation_loop.run_conversation (:1808)   ← 心脏
   │ finally: lease.stop_refresher() → join_threads → clear_interrupt → release
   ▼
结果 dict 返回给调用方（CLI / 网关 / TUI / 桌面 / ACP / cron）

    2. admit_durable_turn_lease —— 跨进程会话租约（turn_facade_lease.py:299）¶

    为什么需要租约？state.db 里的会话被多个进程共享（Desktop、CLI resume、网关、后台投递）， 同一时刻只允许一个进程对一个会话执行 load → run → flush，否则两个进程交错写入 同一份转录就是数据损坏。模块 docstring（:1-8）给出分工：admit_durable_turn_lease 负责拿行级租约（或返回门面必须转交的 early result）；DurableTurnLease 负责周期续租、 看门狗接线、丢租/停滞中断。

    # agent/turn_facade_lease.py:26-31
LEASE_TTL_SECONDS = 300.0      # 行租约的 TTL
LEASE_WAIT_SECONDS = 1800.0    # 最多等另一个进程 30 分钟
_REFRESH_WRITE_PATIENCE_S = 20.0   # 续租等待写锁的耐心
_REFRESH_EXPIRY_MARGIN_S = 2.0     # 距过期的安全余量

# agent/turn_facade_lease.py:299-311（节选）
def admit_durable_turn_lease(
    agent, *, session_id: str, relay_turn_id: str, task_context: dict[str, Any],
    conversation_history: Optional[list[dict[str, Any]]],
) -> TurnLeaseAdmission:
    """Acquire the session turn lease (the row need not exist yet); build (not start) its threads.

    Mutates ``task_context["session_id"]`` and ``agent.session_id`` when the wait forced a resume-id
    reload. Returns an ``early_result`` (interrupted / timed out) instead of a lease when admission
    fails; the caller returns it verbatim."""

    三个值得注意的细节：

    1. 没有行也照样拿租约（:318-326 注释）：客户端自造的 session id 不保证进程唯一， 第一次 turn 可能在中途才建行——若"没有行就不拿租约"，第二个写进程就会拿一个无人 持有的租约、把自己的 turn 插进来。holder 串是 pid=<pid>:turn=<relay_turn_id>:platform=<platform>。
    2. 等到了才重载转录（:378-401）：等待期间上一个持有者可能压缩/轮转了会话； 只有 reload_needed 且行确实存在（或不确定）时才重载——立即拿到租约的快路径跳过 这一步，省一次提示词缓存 miss。
    3. 异常时释放已拿到的租约（:403-406）：except BaseException: lease.release(); raise—— 门面还没见过这个 lease，不能让它泄漏（行永远锁死）。

    等待期间的用户体验在 _on_wait（:336-344）：先提示"另一个 Hermes 进程正在使用此会话， 等待中"，超过 1 秒开始播报已等待秒数。

    3. DurableTurnLease —— 续租与看门狗（turn_facade_lease.py:34）¶

    # agent/turn_facade_lease.py:83-101（节选）
    def start(self) -> None:
        with self._lock:
            self.turn_active = True
        # Stamp the activity clock at turn entry: `_last_activity_ts` persists across turns, so
        # without this the watchdog would measure idle from the PREVIOUS turn and abort a fresh one.
        self.agent._touch_activity("starting new turn")
        ...
        self.timer_handles.append(schedule(self.refresh_tick, self.refresh_interval))  # 默认 60s
        if self.watchdog is not None:
            self.timer_handles.append(self.watchdog.schedule())

    注意：定时器走共享调度器（agent/periodic_scheduler.py），不是每 turn 两个线程。 turn 进入时要摸一次活动时钟——_last_activity_ts 是跨 turn 持久的，不摸的话看门狗 会拿上一个 turn 的尾巴来量这个新 turn，直接误杀。

    续租核心 refresh_tick（:201-258）的语义：续租成功 → _authority_deadline 前移，这是 唯一能移动 deadline 的事情；真正的丢租（rowcount 0）→ _interrupt_turn 无条件打断本 turn——"丢租意味着这个进程已不再拥有该会话"（:130-132 注释），打断不需要 generation 认领； SQLite 锁是"错过一拍"，只有下一次尝试也来不及在过期前落笔时才停 （_stop_on_exhausted_authority，:195-199）；续租 UPDATE 带 holder 限定（fence），防止迟到 的续租者续到后继租约上。

    看门狗接线 build_threads（:62-81）：续租成功 ≠ 有进展——一个静默卡死的 turn 会永远续租。所以可选配置 agent.turn_liveness 会构造 TurnLivenessWatchdog （实现在 turn_liveness.py），停滞即硬中断。commit_liveness_abort（:144-175）是看门狗的 提交点：在 _touch_activity 同一把锁下复核观察到的 (generation, timestamp)， turn 若已复活则拒绝中止（fail-closed 语义是"拒绝中止"而非"强行中止"）。

    5. init 是纯转发器（run_agent.py:236-288）¶

    6. IterationBudget —— 线程安全的迭代预算（iteration_budget.py:25）¶

    # agent/iteration_budget.py:25-56（节选）
class IterationBudget:
    """Thread-safe iteration counter; ``execute_code`` (programmatic tool calling)
    iterations are refunded via :meth:`refund` so they don't eat into the budget."""

    def __init__(self, max_total: int):
        self.max_total = max_total
        self._used = 0
        self._lock = threading.Lock()

    def consume(self) -> bool:
        """Try to consume one iteration.  Returns True if allowed."""
        with self._lock:
            if self._used >= self.max_total:
                return False
            self._used += 1
            return True

    def refund(self) -> None:
        with self._lock:
            if self._used > 0:
                self._used -= 1

    @property
    def remaining(self) -> int:
        with self._lock:
            return max(0, self.max_total - self._used)

    模块 docstring（:1-5）说明预算模型：每个 AIAgent（父或子）各持有一个 IterationBudget；父的上限来自 max_iterations，每个子代理用 delegation.max_iterations（config_migrations.py:779-787 记录了它从 50 提到 250——50 会 截断扎实的委派工作），所以父子总迭代数可以超过父的上限。consume/refund 在主循环与 工具轮里被调用：只有 execute_code（程序化工具调用）的轮次直接退款 （turn_tool_round.py:207-208）——廉价 RPC 式调用不该吃掉预算。

    总结¶

    • 门面三层：AIAgent（Mixin 拼装 + _forward）→ TurnFacadeMixin.run_conversation （安检门）→ conversation_loop.run_conversation（心脏）。每层只做自己的事。
    • 安检门五步：后台 review 让路 → 跨进程租约准入 → relay/accounting/portal 作用域 → 中断/父子绑定 → lease.start() 后转发；finally 对称释放每一个，无条件复位。
    • 租约 = 会话的进程级互斥锁：TTL 300s、最多等 1800s；续租成功是唯一移动 deadline 的 事件；丢租无条件硬中断；看门狗防"静默卡死但租约健康"；wait 被打断时用户输入由 carry_unadmitted_user_message 转存，不丢消息。
    • 构造即打包：__init__ 把 ~60 个参数打包转给 init_agent，相位顺序 （路由→缓存→client→工具→会话→记忆→压缩→快照）load-bearing。
    • 预算模型：max_iterations 默认 sys.maxsize（不限），实际闸门是线程安全的 IterationBudget（父上限、子代理独立、execute_code 退款）；主循环还有 _budget_grace_call 一次宽限，让预算耗尽时能产出体面的总结。
