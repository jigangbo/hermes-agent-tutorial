    relay_moa.md — NeMo Relay 观测运行时与 Mixture-of-Agents:作用域栈、多模型备援循环与 bot 链防环¶

    文件概览¶

    本篇讲 agent 侧两套"多模型协作"机制,外加两个模型行为调节器。先澄清一个容易望文生义的点: relay_*.py 的 relay 指的是 NeMo Relay——NVIDIA 的 LLM 观测/追踪管线,不是 CLI 与网关之间 的"消息中继面"。Hermes 把 Relay 嵌成代理执行的观测骨架:每个会话一根作用域栈(Agent scope),每个 turn 一个 Function scope,每次 LLM 尝试/工具执行/压缩都作为 span 挂到正确的父 节点上;用户配置 Relay 导出器即可看到全链路,Hermes 自己不添任何出站路径。

    MoA(Mixture-of-Agents)则是备援的智力面:/moa 把一个 user turn 标记为 MoA 开启,正常 agent 循环照旧持有工具调用与终止权,moa_loop.py 只在每次模型迭代前并行征询若干参考模型 (advisor),把它们的建议合成"引导块"附加给聚合器(aggregator,即当前 acting model)。引导块 作为独立的尾部 user 消息追加——这是全篇最重要的缓存决策。bot_chain.py 防 bot-to-bot 死循环,fast_mode.py 管有界快窗。

    Relay 作用域栈(每会话一栈,turn 之间 LIFO):

    关键代码走读¶

    1. RelayRuntime:一个进程、多个 profile、每会话一根栈¶

    RelayRuntime 构造时做三件事:加载 nemo-relay 库、认领当前 profile、加入进程级插件配置。 会话表按 session_id 存 RelaySession(每会话一根隔离的作用域栈 + 自己的 RLock + 关闭状态 + 段轮转旗标):

    self.profile_key = profile_key or current_profile_key()
    self.runtime_id = uuid.uuid4().hex
    self._sessions_lock, self._execution_consumers_lock = threading.RLock(), threading.RLock()
    self._sessions: dict[str, RelaySession] = {}
    ...
    self._plugin_configuration_state = _PLUGIN_CONFIGURATION.acquire(self, self.relay)

    会话 scope 的开栈是有界异步的:_open_session_scope 把 scope.push 提交到 8 工人的 daemon 池,future.result(timeout=SCOPE_OP_TIMEOUT=10s)——一根卡死的管线最多损失一个 span,永远不会 堵住 agent。子代理的 scope 挂在派生它的 turn/session handle 之下 (metadata["nemo_relay_scope_role"]="subagent"),父会话不存在时 resolve_parent 先建它。

    2. turn 生命周期:begin_turn / end_turn 与并发守卫¶

    同一会话的两个并发 Hermes turn 共享物理作用域栈——后开者的兄弟 scope 关闭时不满足 LIFO。 begin_turn 用 active-turn 表守卫:发现并发就关掉本 turn 的 Relay 插桩,只损失观测、不损失 正确性:

    # agent/relay_runtime.py:1046-1089(节选)
def begin_turn(self, lease, *, turn_id: str, task_id: str, metadata=None) -> RelayTurnContext:
    if lease.released:
        raise RuntimeError("Hermes Relay conversation lease is released")
    turn = RelayTurnContext(lease=lease, turn_id=turn_id, task_id=task_id)
    key = (lease.profile_key, lease.session_id)
    with self._active_turns_lock:
        if self._active_turns.get(key):
            # One physical scope stack per session; concurrent turns' sibling scopes would not close LIFO.
            turn.relay_enabled = False
            logger.warning("Skipping Relay instrumentation for concurrent Hermes turn %s in session %s", ...)
        else:
            self._active_turns[key] = {id(turn)}
            turn._active_registered = True
    host = lease.live_runtime() if turn.relay_enabled else None
    if host is not None:
        # Rotation happens HERE: no live turn scope on the stack, so the session scope can close/reopen LIFO.
        _warn_on_error("segment rotation", self._maybe_rotate_segment, host, lease.session)
        ...
        turn.handle = _warn_on_error("turn initialization", host.run_in_session, lease.session,
            host.relay.scope.push, TURN_SCOPE, host.relay.ScopeType.Function, handle=lease.session.handle,
            input=_scope_input(lease.turn_cwd), metadata=turn_metadata, timeout=SCOPE_OP_TIMEOUT)
    turn._previous_turn = _CURRENT_TURN.get()
    _CURRENT_TURN.set(turn)
    return turn

    两个设计点:段轮转(压缩或 max_turns 触发的 session scope 关闭重开)只发生在 turn 边界—— 这是唯一 LIFO 安全的时点,压缩打旗标、begin_turn 消费;_CURRENT_TURN ContextVar 把"当前 turn"带给深层代码(relay_compaction._turn_target 用它寻挂载点)。end_turn(relay_runtime.py:1100) 幂等;pop_relay_scope_if_top(relay_runtime.py:118)拒绝弹出兄弟之上的 scope,真实输出存进 _deferred_scope_outputs,由会话关闭排水收尾。

    3. LLM 尝试与工具执行:托管判定 + 回调 guard¶

    每次物理 provider 尝试若落在托管执行里,_ManagedAttempt.resolve 组装请求状态:请求体经 Relay codec 做往返基线(_codec_round_trip_request_body),让拦截器改写后的请求与原请求可比。 协议名按 api_mode 归一化:

    # agent/relay_llm.py:31-35 + 58-71(节选)
_RELAY_PROTOCOL_BY_API_MODE = {
    "chat_completions": ("openai.chat_completions", "OpenAIChatCodec"),
    "codex_responses": ("openai.responses", "OpenAIResponsesCodec"),
    "anthropic_messages": ("anthropic.messages", "AnthropicMessagesCodec"),
}

class _ManagedAttempt:
    @classmethod
    def resolve(cls, session_id, request, metadata, *, name: str, model_name: str):
        """Return the managed attempt for ``session_id`` ..., or None to run unmanaged."""
        if session_id is None:
            session_id = _current_session_id()
        if not session_id:
            return None
        runtime, session, parent = relay_runtime.resolve_execution_context(session_id)
        if runtime is None or session is None or not runtime.managed_execution_enabled():
            return None
        return cls(runtime, session, parent, request, metadata, name=name, model_name=model_name)

    回调跑在捕获上下文的副本里(self.context = contextvars.copy_context()),且套 managed_callback_guard()——Relay 管线驱动流时,回调内部发起的嵌套 relay 调用必须绕过托管 (#77244:管线的 Future 绑定在正在被阻塞的循环上)。工具侧 relay_tools.execute(relay_tools.py:16) 同一套路:先判托管,让 Relay 拦截器有机会改写工具参数(invoke 收 next_args),回调全程 guard。流式侧的对称件是 chat_completion_helpers_relay.py 的 RelayChatAccumulator:Relay 的 finalizer 在 provider 流结束时立刻跑,与 Hermes 消费线程并发——它只能用自己 collector 观测 到的状态重建响应,绝不能碰消费者闭包里的东西。

    4. 压缩标记与 cwd:挂对父节点¶

    relay_compaction.py 处理一个只有观测层才有的问题:压缩发生在 turn 外(网关卫生)时没有活 turn scope,mark 该挂哪?寻挂顺序是"同会话的活 turn → 该会话的 session scope → 压缩 agent 启动 时所在的活 turn",而Relay 只对持有压缩标记的 agent scope 重置 LLM 历史新鲜度——挂错父 节点,下一条 LLM span 就不会重新记录完整历史。mark 是纯观测:一次停滞发布就让本进程对 Relay 停止等待(有界超时),导出器由用户配置、mark 不添出站路径。relay_cwd.py 为 scope input 提供 逻辑 cwd:任务可用与所属会话不同的 worktree,远程路径按声明保留、未知路径省略而不是拿 Hermes 主机的 cwd 顶替。

    MoAChatCompletions 是 OpenAI-chat 兼容门面:client.chat.completions.create() 长着 SDK 的 脸,内部做参考扇出 + 引导注入 + 聚合器请求:

    扇出有节奏(_fanout_cache_key,moa_loop.py:1272):默认 user_turn 只哈希到最后一条真实 user 消息为止的前缀——工具迭代 2+ 全是缓存 HIT,advisor 每 user turn 只跑一次(合成在开头, acting model 随后独力干活,原始 MoA 形态);per_iteration 每次工具迭代重跑;every_n:<N> 折中, 迭代 1 与每第 N 次上节奏,中间复用上一次的引导。参考调用走 _run_references_parallel(≤8 workers),失败变模型专属占位而非炸循环;advisor 输出先过中央脱敏器再过 MoA 自己的 email/ 电话模式(电话模式刻意要求分隔符,免得误伤行号/日期/SHA/IP)。usage/成本按 advisor 自己的 费率计价再美元求和(_RefAccounting),中断后迟到的 future 回调经 _fold_pending_accounting 补账(只加不覆,流式重试不重复计)。

    6. 引导块的缓存经济学:_attach_reference_guidance¶

    这是 moa_loop 全文最贵的一课。引导块每 turn 都不同,追加它有两种位置选择,而其中一种曾经把 缓存打回原点(#112358):

    # agent/moa_loop.py:1021-1036
def _attach_reference_guidance(agg_messages: list[dict[str, Any]], guidance: str) -> None:
    """Attach the per-turn reference block as its OWN trailing user message.

    The block varies per turn; appending keeps ``[system][task][tool-history]``
    cache-stable. It is never merged into a trailing user turn: iteration 1 of a
    tool loop ends on ``user(task)``, and a merged ``user(task + guidance)`` byte-differs
    from the ``user(task)`` every later iteration replays, so the provider prefix cache
    collapsed to the system prompt on iteration 2 of every turn (#112358). Converters
    that require strict alternation (Anthropic Messages, Converse, native Gemini) merge
    the two user turns as SEPARATE content blocks, so the task block stays byte-stable
    there too; on the OpenAI-compatible wire the request ends ``user(task), user(guidance)``,
    which a chat template that enforces strict user/assistant alternation rejects."""
    agg_messages.append({"role": "user", "content": guidance})

    读三遍:合并进尾部 user turn,迭代 1 的 user(task + guidance) 与迭代 2 起重放的 user(task) 字节不同——每次 turn 的第二次 API 调用,缓存就从系统提示词重新开始。"独立的尾部 user 消息" 则让 [system][task][tool-history] 全程字节稳定。代价是 OpenAI wire 上出现相邻 user 对,严格 交替的聊天模板(llama.cpp/vLLM Jinja、Mistral、部分 OpenRouter)会 400——这正是 moa_alternation.py 的活:被 400 判定为 FailoverReason.role_alternation 后只对这一个目的 地合并重试一次,并在门面上记住 (route, model),后续迭代预合并、永不付第二次 400;接受分离 形状的目的地永不被触碰。peel_reference_guidance 是精确逆操作,让缓存断点绝不落在每 turn 变化 的引导上。

    7. 参考系统的"自白书"、one-shot 路径与追踪¶

    advisor 看到的是一份咨询视图(_reference_messages):工具结果被头尾预览到 4000 字符(工具 调用保留全文),外加一条把它们钉在"顾问"位置上的系统提示词——没有它,advisor 会以为自己是 acting agent,拒绝执行或假装执行:

    "You are a reference advisor in a Mixture of Agents (MoA) process. You are "

    "tools, run commands, browse, or access files, repositories, or URLs, and "
    "you should not try to or apologize for being unable to. A separate "

    "actual actions.\n\n"

    8. bot_chain.py:跳数属于运行时,不属于模型¶

    Bot Mode 允许 bot 互发消息,死循环防护的全部状态由运行时持有:跳数骑在投递的 author envelope(hops)里,只有运行时写它,模型无法重置;超过 gateway.bot_loop_guard.max_hops 拒发。 同链内"同文同收件人"按 body 摘要去重;"回复不需要回复"的消息置 notify-only,且该 turn 不得再 回消息给对方:

    # agent/bot_chain.py:139-157(节选)
def admit_send(agent: Any, recipients: list[str], body: str) -> Admission:
    """Check one ``message_agent`` call to ``recipients`` ... Admitted recipients reserve their
    ask and the call's hop until ``Admission.release``."""
    settings = _settings()
    if not settings.enabled:
        return Admission()
    author = getattr(agent, "_turn_author", None) or {}
    author_id = str(author.get("id") or "") if author.get("is_bot") else ""
    digest = hashlib.sha256(" ".join(str(body).split()).encode()).hexdigest()
    with _LOCK:
        key = _bound_key(agent)
        state = _CHAINS.setdefault(key, _new_state(time.monotonic()))
        bot_turn = state["hops"] > 0
        hop = state["sent"] + 1 if bot_turn else 1
        if hop > settings.max_hops:
            return Admission(refusal=(
                f"This bot-to-bot exchange already reached its limit of {settings.max_hops} messages "
                "(gateway.bot_loop_guard.max_hops), so nothing was sent. Do not retry; finish your turn "
                "and tell your user where it stands."))

    链状态按 session_id 键存进程级 _CHAINS,而非挂在 agent 上——网关可能在 turn 间重建 agent,丢了计数等于送新预算;压缩轮转让 session_id 变更时 carry_chain 把条目跟着搬。人发言即 断链(旧条目删除);拒绝文案直接给模型行为指令("Do not retry")。Admission.release 处理 "确定没发出去"的回收:撤销 ask 预订,整 call 无一送达时连 hop 也退回,重试既不算重复也不算 新跳。

    9. fast_mode.py:有界快窗与字节不变性¶

    /fast auto 让每个 user turn 开一个 agent.fast_auto_seconds(默认 60s)的窗口,/fast cold 只在无历史的会话首 turn 开。窗口只影响每请求参数(service_tier/speed),请求体其余部分 字节不变——这是它对提示缓存无副作用的全部理由。Anthropic 为每个 speed 单独留一份提示缓存, 所以 Anthropic 的窗口边界注定重写一次前缀(文档里明说,当作已知代价):

    总结¶

    这两套机制是"多模型"的两种正交形态:Relay 是看——一次 LLM 调用在观测骨架里留下完整的 父子 span 链,而它对执行的唯一介入是"被拦截器改写",所以整套集成最重的工程都在边界条件上 (并发 turn 不 LIFO、回调重入、codec 往返基线、10s 有界 scope 操作);MoA 是想——acting model 的权力一寸不让,advisor 只提供私有引导,而引导块的每一点形状(独立尾部消息、扇出节奏、 peel 逆操作)都由提示缓存经济学决定。bot_chain 和 fast_mode 则示范了两个纪律:防环状态必须放 在运行时手里(envelope 由 runtime 写、session_id 键控),请求调优必须收敛到单表单字段 (SERVICE_TIER_WORDS)以保请求体字节稳定。一句话:观测可以失败(有界、警告、跳过),引导 可以缺失(占位、降级),缓存前缀不能变。
