    03_agent — Agent 核心模块总览¶

    agent/ 是 Hermes 的心脏：一条用户消息从进入 AIAgent.run_conversation 到变成最终回答， 经历租约准入 → turn 前奏 → 组装请求 → 调用模型 → 执行工具 → 收尾持久化的完整管线， 全部住在这个目录的约 200 个文件里。本篇是导航地图。

    规则提醒（根 AGENTS.md）：文件 ≤ 2,000 行、新函数 CC ≤ 20——已超限的单元"只许变小"。 所以 top 8 里的大文件都是历史上已定型的候选拆分对象，阅读时优先找它的 facade（公开入口）和 siblings（同前缀兄弟文件）。

    facade + siblings 设计模式¶

    agent/ 是这个模式的范本（根 AGENTS.md § Project Structure）：

    run_agent.py（facade，1,565 行）            agent/conversation_loop.py（实现，1,967 行）
  class AIAgent(14 个 Mixin)                 def run_conversation(agent, ...)
      __init__ ──打包 locals()──►  agent/agent_init.py::init_agent
      run_conversation ──转发──►   ── lease 准入后 ──►
      _execute_tool_calls ──►      agent/tool_executor.py（siblings 之一）
      switch_model ──_forward──►   agent/agent_runtime_helpers.py

    四条规则（读代码时随时用得上）：

    1. 门面保留：公共入口 + 其他包 import 的名字；行为住在兄弟文件 <stem>_<topic>.py，每个文件管一个主题（turn_tool_round.py 只管一轮工具调用）。
    2. 按主题找代码：grep -rn "def run_tool_round" agent/turn_*.py， 不要通读门面。
    3. 兄弟文件在函数体内 late-import 门面（from agent.conversation_loop import X）， 绝不模块级循环。这同时定义了测试缝：patch 生产代码真正读取的位置 （patch("agent.conversation_loop.X")）。
    4. super god-file 的拆分方式：turn 循环拆成了 33 个 turn_*.py，每个阶段一个文件； 主循环只剩"串阶段"的 _run_phase 机制。

    一条不变量贯穿所有文档¶

    Per-conversation prompt caching is sacred（会话级提示词缓存神圣不可侵犯）。

    • 系统提示词每会话构建一次、字节冻结，唯一合法的变异是压缩 （system_prompt.md）；
    • 请求历史通过 api_content sidecar 重放"当初发送的精确字节"，请求组装时 cache plan 永远最后构建（turn_pipeline.md）；
    • 中途注入的一切（steer、内存预取、预算警告）都骑在最新的工具结果行上， 已持久化的行绝不改写（conversation_loop.py:139-158 的注释是范本）；
    • 主循环是同步的：任何"换个上下文就想重建提示词"的冲动，都请回到这条不变量上自问。

    阅读路径建议¶

    零基础读者推荐顺序：

    1. 本篇（全景图）→ 2. turn_facade.md（消息如何进门） → 3. conversation_loop.md（循环如何转） → 4. turn_pipeline.md（每个阶段做什么） → 5. system_prompt.md（为什么提示词动不得） → 6. compression / model_providers 等后续文档（边缘系统）。

    动手改代码前的三件套：读 agent/AGENTS.md（模块规则）、跑 grep -rn "def <符号>" agent/turn_*.py 定位实现、用 scripts/run_tests.sh 的 tests/agent/ 套件验证消息形状不变量（角色交替、字节稳定系统提示词）。
